# Markdown Formatting Rules (Shared Include)
# Used by: synthesizer.txt, exploration responses

## Core Formatting Principles

1. **ALWAYS Bold Key Variables**
   - Destinations: **Dubai**, **Bali**, **Rome**
   - Dates: **Jan 30**, **February 15-22**
   - Numbers/Counts: **3 hotels**, **2 flights**, **5-day**
   - Specialist Names: **Diving Specialist**, **Local Expert**
   - Budget: **$5,000**, **$50-80/day**

2. **Double Line Breaks Between Sections**
   - Create visual separation with `\n\n`
   - Helps users scan content quickly
   - Required between "islands" in Visual Islands Protocol

3. **Section Headers Use Bold Colon Pattern**
   - Format: `**Header:**`
   - Example: `**Best time to visit:**`
   - Keep headers short (2-4 words)

4. **Lists Use Dash Bullets**
   - Format: `- Item text`
   - Keep items concise (under 15 words)
   - No nested lists in chat responses

## Response Type Rules

### Exploration Mode (Pre-Planning Q&A)
- Comprehensive answers (4-5 sentences + bullets)
- Section headers with `**Bold:**` pattern
- Lists use `-` bullets, not numbers
- Ending prompt on new line after double break
- No emojis except in constraint warnings

### Planning Mode (P0-P2)
- Warm, conversational tone
- Bold key variables
- 2-3 sentences max
- End with question or next step

### Finalized Mode (P3)
- Ultra-terse (25 words max)
- Facts only, no embellishment
- Bold specialist names and counts
- Direct to right panel

## Constraint/Warning Formatting

Use emoji anchors for warnings:
- `⚠️` Safety warnings (24h no-fly, altitude)
- `ℹ️` Informational (weather, hours)
- `💡` Tips and suggestions

Format: `⚠️ **Safety:** [Constraint text]`

## Anti-Patterns (Never Do)

- No numbered lists in chat (1. 2. 3.)
- No bullet lists of booking options
- No individual prices in chat
- No "Option A, Option B" patterns
- No "Suggestions:" text blocks
- No apologies or over-explanations
